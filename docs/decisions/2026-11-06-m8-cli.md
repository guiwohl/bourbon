# M8 CLI

Decided by Claude during the autonomous run; review at the UI pass.

| # | Decision |
|---|---|
| 1 | New crate `crates/bourbon-cli`, binary `bourbon`, depends only on `bourbon-core`. No clap: a pure `parse` function returns a `Command` enum |
| 2 | `bourbon get <id>` opens the default database and prints the note in the export format (frontmatter + blank line + body) via `NoteStore::note_markdown`, which reuses the export renderer. Works for templates. Trashed or unknown id: stderr, exit 1. Malformed id: stderr, exit 2. Nothing else is written anywhere |
| 3 | `bourbon` with no arguments spawns `bourbon-app` (next to the executable, else on `PATH`) detached with null stdio and exits 0; failure: stderr, exit 1 |
| 4 | `--help`/`-h` prints usage on stdout; `--version`/`-V` prints `bourbon <version>`; any other input prints usage on stderr, exit 2 |
| 5 | `run(arguments, database_path, launch_app, stdout, stderr) -> u8` holds the logic; tests use an on-disk temp database and assert exact bytes and exit codes. One integration test runs the real binary with `XDG_DATA_HOME` set |
| 6 | The editor header "..." menu and the control pane both offer "Copy CLI command", writing `bourbon get <id>` to the clipboard through one shared function (`cli_command`) |
| 7 | `just architecture` also checks that `bourbon-cli` has no `gpui*` dependency; `deny.toml` needs no change (only gpui crates are listed) |
