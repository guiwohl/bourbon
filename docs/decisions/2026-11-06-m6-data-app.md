# M6 data in the app: backup, restore and export

Decided by Claude during the autonomous run; review at the UI pass.

Binding rows: foundation 10-13. Builds on [the M6 core](2026-11-06-m6-data-core.md).

| # | Topic | Decision |
|---|---|---|
| 1 | Settings | `backup_repository` (`owner/name`, validated with `GitHubRepository::parse`), `backup_auth` (`gh_cli` default, or `token`), `backup_enabled` (default off); same tolerant parsing as the rest |
| 2 | Token | Never in `settings.toml`. `TokenFile` writes `$XDG_CONFIG_HOME/bourbon/backup-token` with mode 0600 (temp file plus rename) |
| 3 | Settings screen | "Backup" section: repository field with inline error, auth choice, masked token field (only for Token), automatic toggle, "Back up now", "Restore from backup…", status line |
| 4 | Menu | A "⋯" button tops the sidebar: Back up now, Restore from backup…, Export to Markdown…, Settings (`Ctrl+,`). The same three data actions are in the control pane |
| 5 | Runner | Trait `BackupRunner` (`back_up`, `restore`) behind `Locations`; the real one opens a second `NoteStore` on the database file in the background thread, so the UI never blocks. Tests inject a recording fake; the real one is tested against a local bare repository. Errors are plain strings, already scrubbed of the token by the core |
| 6 | Work dir | `$XDG_CACHE_HOME/bourbon/backup`, else `~/.cache/bourbon/backup` |
| 7 | Triggers | Manual; automatic 5 minutes after the last edit (timer restarts on each edit) when enabled; on window close if enabled and something changed since the last backup, after the pending save is flushed. Close is held until the backup ends, at most 20 s, and also when it fails. One backup at a time |
| 8 | Status | "Last backup HH:MM" (local), "Up to date" (core said `Unchanged`) or the error. Errors also go to the red banner |
| 9 | Restore | Confirmation panel (always visible, not in the sidebar): "Replace all notes with the backup from owner/name? Your current notes are saved to bourbon.db.before-restore." On confirm: flush, `snapshot` to `<data dir>/bourbon.db.before-restore` (replacing an older copy), swap the store for an in-memory placeholder, restore in the background, reopen the store, go to All Notes, clear selection and history, reload. A failure reopens the old database and shows the error. Refused while a backup runs |
| 10 | Export | "Export to Markdown…" asks for a directory (`prompt_for_paths`) and exports into `Bourbon export YYYY-MM-DD HHMM` (local time). Result: a neutral banner "Exported N notes to …" cleared by the next edit; failures use the red banner |
| 11 | Dirty tracking | Any autosave restart or listing refresh marks the data dirty and (re)starts the timer; startup does not |
