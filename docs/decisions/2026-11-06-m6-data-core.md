# M6 data core: export and backup engine

Decided by Claude during the autonomous run; review at the UI pass.

Binding rows: foundation 7, 9-13, 19. Scope: `bourbon-core` only; the app and CLI wiring come later.

## Export

| # | Topic | Decision |
|---|---|---|
| 1 | API | `NoteStore::export_markdown(&Path) -> ExportSummary { notebooks, notes, templates }`. The destination must not exist or be an empty directory, else `ExportDestinationNotEmpty` |
| 2 | Atomicity | Everything is written into a hidden temp folder next to the destination and renamed into place; a failure leaves nothing behind |
| 3 | Folders | One folder per notebook, nested like the tree. Name: `/` and NUL become `-`, trimmed, empty/`.`/`..` become `untitled`, cut at 200 bytes. Same-named siblings: oldest keeps the name, then `-1`, `-2` (age, then id) |
| 4 | Files | `<slug>.md`. Slug: lowercase, ASCII letters and digits kept, other runs become one `-`, trimmed, max 100 chars, empty is `untitled`. Common Latin accents are transliterated (`é` to `e`, `ß` to `ss`, `æ` to `ae`); other non-ASCII letters are dropped without a separator. Duplicates numbered like folders |
| 5 | Frontmatter | `id`, `title`, `tags` (names, `[]` when none), `created`, `updated` (RFC 3339 UTC), `---`, blank line, body untouched. Strings are always double-quoted with YAML escapes |
| 6 | Content | Trashed notes are skipped. Templates go flat into top-level `_templates/` with the same naming rules; a notebook called `_templates` is renumbered |

## Backup

| # | Topic | Decision |
|---|---|---|
| 7 | Snapshot | `NoteStore::snapshot(&Path)`: `VACUUM INTO` (target must not exist), then a read-only `PRAGMA integrity_check`; anything but `ok` removes the file and fails |
| 8 | Remote | `BackupRemote { url: RemoteUrl, token: Secret }`. `RemoteUrl` is a GitHub https URL built from a validated `GitHubRepository` (`owner/name`) or a `file://` path (tests) |
| 9 | Token | `Secret` never prints its value in `Debug`. Sources: `Secret::from_gh_cli()` (`gh auth token`) or `Secret::new(pat)` |
| 10 | Push | `backup(store, remote, work_dir)`: snapshot into a temp repo, SHA-256; equal to the last pushed hash (file `last-pushed.sha256` in `work_dir`) gives `Unchanged`. Otherwise one commit with only `bourbon.db`, author `Bourbon <bourbon@localhost>`, branch `main`, `push --force`. The hash is recorded only after a successful push |
| 11 | Auth | `-c http.extraHeader=Authorization: Basic base64(x-access-token:<token>)`; the token is never in a URL. git stderr is scrubbed of the token and its encoded form. git runs with global/system config disabled and no prompts. A missing `git` is `GitNotInstalled` |
| 12 | Restore | `restore(remote, destination_db, work_dir)`: shallow clone of `main`, integrity check of the fetched `bourbon.db`, copy to a sibling temp file, atomic rename. Any failure leaves the destination untouched. The caller must close the store first (and no stale `-wal`/`-shm` may remain) |
| 13 | Dependencies | `sha2`, `base64`; `tempfile` is now a runtime dependency (staging folders) |
